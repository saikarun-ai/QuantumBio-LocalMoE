# Evaluation Evidence Package

This folder stores the raw and processed evidence behind `docs/EVALUATION_REPORT.md`.

## Layout

```
evaluation/
├── README.md
├── reproduce.sh / reproduce.bat   # one-command regeneration
├── benchmark/                     # benchmark programs (idempotent, write JSON)
│   ├── toolbox.py                 # shared helpers / sys.path bootstrap
│   ├── environment.py             # hardware + software versions
│   ├── routing_benchmark.py       # 231 labelled prompts, latency percentiles
│   ├── quantum_benchmark.py       # QASM validation corpus, VQE, reproducibility
│   ├── offline_check.py           # source audit + live socket watch
│   ├── reliability_test.py        # 100 rounds of API calls + 5 chat calls
│   ├── api_extended_test.py       # model select, error mapping, prompts, LLM reports
│   ├── quantization_benchmark.py  # size / RAM / tok/s / latency per GGUF
│   ├── speculative_test.py        # target-only vs target+draft
│   ├── scientific_task.py         # 8 MCQs + 2 LLM OpenQASM generations
│   └── process_results.py         # aggregates raw -> results/processed/summary.json
├── datasets/
│   └── routing_prompts.json       # generated by routing_benchmark.py
├── results/
│   ├── raw/                       # JSON produced by the benchmarks (source of truth)
│   ├── processed/
│   └── figures/
├── logs/
└── configs/
```

To keep the repo small, generated JSON lives only in `results/raw/`; every number in the
evaluation report is traceable to one of those files.

## Running

Windows: `evaluation\reproduce.bat`
Linux/macOS: `./evaluation/reproduce.sh`

Optional dependency for resource measurements: `pip install psutil`.

## Model availability

Only the GGUFs found by the model registry are benchmarked. In this environment:

| Model | Quant | Size |
| --- | --- | --- |
| gemma-3-1b-it | Q4_K_M | 0.81 GB |
| DeepSeek-R1-Distill-Qwen-1.5B | Q6_K_L | 1.58 GB |
| Phi-3-mini-4k-instruct | Q4 | 2.39 GB |

FP16 / INT8 / AWQ-INT4 rows are reported as **unavailable** because no such weights exist
locally. `qiskit-aer` **0.17.2 is installed** (with `vcomp140.dll` copied into
`qiskit_aer/backends/`), so `simulate_qasm` returns live counts — see
`evaluation/results/raw/quantum_benchmark.json`. Docker is **absent**, so
Postgres/Redis/Qdrant tests fall back to in-memory stores.
